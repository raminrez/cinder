# Accordion

An Accordion is a vertically stacked set of collapsible panels that allows users to reveal or hide sections of related information. It is ideal for progressive disclosure in FAQ pages, product configurations, policy documentation, and dense inspection panels.

Built on React Aria Components' `DisclosureGroup` and `Disclosure` primitives, Hashti's Accordion manages expand/collapse state, chevron animations, correct semantic heading levels, and keyboard interactions out of the box.

---

## Import

```tsx
import { Accordion, AccordionItem } from "@cinder/react";
```

---

## Examples

### Basic Accordion

Construct an accordion by nesting multiple `<AccordionItem>` components inside an `<Accordion>`. Each item takes a `title` string or element and renders its children within the collapsible panel:

```tsx
import { Accordion, AccordionItem } from "@cinder/react";

export function BasicAccordionExample() {
  return (
    <Accordion className="max-w-xl">
      <AccordionItem id="item-1" title="What is Hashti's spatial philosophy?">
        Hashti (هشتی) represents the vaulted, octagonal threshold in classical Persian architecture.
        It acts as a tranquil pause between bustling external inputs and domestic serenity.
      </AccordionItem>

      <AccordionItem id="item-2" title="How does Hashti achieve WCAG 2.2 AAA conformance?">
        Hashti guarantees minimum 7:1 contrast ratios on essential typography, full keyboard parity,
        unobtrusive live announcements, and strict WAI-ARIA landmark structures.
      </AccordionItem>

      <AccordionItem id="item-3" title="Which browsers and runtimes are supported?">
        All modern evergreen browsers (Chrome, Edge, Firefox, Safari) along with SSR runtimes
        including Next.js App Router, Astro, Remix, and Vite.
      </AccordionItem>
    </Accordion>
  );
}
```

### Multiple Expansion Mode

By default, an accordion allows only one item to be open at a time (closing the previous panel when a new one opens). Set `allowsMultipleExpanded` to allow multiple panels to remain open simultaneously:

```tsx
import { Accordion, AccordionItem } from "@cinder/react";

export function MultiExpandedAccordionExample() {
  return (
    <Accordion allowsMultipleExpanded defaultExpandedKeys={["network", "storage"]}>
      <AccordionItem id="compute" title="Compute Configuration">
        <p className="text-sm">Configure CPU allocation, worker isolation, and memory boundaries.</p>
      </AccordionItem>

      <AccordionItem id="network" title="Networking & Ingress">
        <p className="text-sm">Manage edge routing rules, TLS 1.3 termination, and custom domains.</p>
      </AccordionItem>

      <AccordionItem id="storage" title="Persistent Object Storage">
        <p className="text-sm">Set up R2 replication buckets and asset caching headers.</p>
      </AccordionItem>
    </Accordion>
  );
}
```

### Controlled Expansion State

Use `expandedKeys` and `onExpandedChange` to control which accordion panels are opened programmatically:

```tsx
import { useState } from "react";
import { Accordion, AccordionItem, Button } from "@cinder/react";

export function ControlledAccordionExample() {
  const [expandedKeys, setExpandedKeys] = useState<Set<React.Key>>(new Set(["panel-1"]));

  const toggleAll = () => {
    if (expandedKeys.size > 0) {
      setExpandedKeys(new Set());
    } else {
      setExpandedKeys(new Set(["panel-1", "panel-2"]));
    }
  };

  return (
    <div className="space-y-4 max-w-xl">
      <Button size="sm" variant="secondary" onPress={toggleAll}>
        {expandedKeys.size > 0 ? "Collapse All" : "Expand All"}
      </Button>

      <Accordion
        allowsMultipleExpanded
        expandedKeys={expandedKeys}
        onExpandedChange={setExpandedKeys}
      >
        <AccordionItem id="panel-1" title="Security & Compliance">
          SOC 2 Type II audit report available for enterprise accounts.
        </AccordionItem>
        <AccordionItem id="panel-2" title="Encryption at Rest">
          All customer datasets are encrypted using customer-managed AES-256 keys.
        </AccordionItem>
      </Accordion>
    </div>
  );
}
```

### Semantic Heading Levels

To preserve proper document outline hierarchy for screen readers and search engines, specify the `headingLevel` (1 through 6, default 3) on `<AccordionItem>`:

```tsx
import { Accordion, AccordionItem } from "@cinder/react";

export function HeadingLevelExample() {
  return (
    <section>
      <h2 className="text-lg font-semibold mb-3">Frequently Asked Questions</h2>
      <Accordion>
        <AccordionItem id="faq-1" headingLevel={3} title="How are updates published?">
          Packages are distributed via npm and tagged with semantic versioning.
        </AccordionItem>
        <AccordionItem id="faq-2" headingLevel={3} title="Can I use custom themes?">
          Yes, Hashti exposes comprehensive CSS custom property tokens that can be overridden at the root layer.
        </AccordionItem>
      </Accordion>
    </section>
  );
}
```

## Props Reference

### Accordion Props

| Prop | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Height and padding density of accordion item triggers. |
| `allowsMultipleExpanded` | `boolean` | `false` | Whether multiple accordion items can be expanded simultaneously. |
| `expandedKeys` | `Iterable<Key>` | — | The keys of currently expanded items (for controlled state). |
| `defaultExpandedKeys` | `Iterable<Key>` | — | Initial expanded keys when uncontrolled. |
| `onExpandedChange` | `(keys: Set<Key>) => void` | — | Callback fired when expanded items change. |
| `disabledKeys` | `Iterable<Key>` | — | Keys of items that are disabled and cannot be expanded. |
| `className` | `string` | — | Additional CSS class names. |

### AccordionItem Props

| Prop | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `title` | `ReactNode` | **Required** | The header label rendered inside the interactive trigger button. |
| `children` | `ReactNode` | **Required** | Content rendered inside the expandable panel container. |
| `id` | `Key` | — | Unique identifier for tracking expansion state. |
| `headingLevel` | `1 \| 2 \| 3 \| 4 \| 5 \| 6` | `3` | The HTML heading level (`<h1>` - `<h6>`) wrapping the button trigger. |
| `isExpanded` | `boolean` | — | Controlled expansion state for an individual item. |
| `defaultExpanded` | `boolean` | `false` | Uncontrolled initial expansion state. |
| `isDisabled` | `boolean` | `false` | Whether this specific item is disabled. |

## Accessibility (a11y)

- **WAI-ARIA Accordion Pattern**: Built on native `<button>` triggers nested inside semantic `<h*>` headings, paired with associated panel regions.
- **Dynamic Attributes**: Trigger buttons dynamically manage `aria-expanded="true"` or `"false"`, while the panel is linked via `aria-controls` and `aria-labelledby`.
- **Keyboard Interactions**:
  - Press <kbd>Enter</kbd> or <kbd>Space</kbd> on a focused header trigger to toggle panel visibility.
  - Press <kbd>Tab</kbd> to move into interactive content inside the opened panel.
- **Smooth Chevron Rotation**: The chevron icon rotates 90 degrees smoothly via CSS transformations and respects `prefers-reduced-motion` settings.
